Fit note — the 800 × 500 composition The frame above is exactly 800 × 500 CSS px and the complete Home view fits inside it with nothing cut off and no scrolling: clock/weather row, compact Alerts tile, and both rows of shutter cards. How: the tile is a compact banner (one title line + one info line, display-only, no buttons), the shutter buttons keep their real 70px height, and there is no Home Assistant app bar — Fully Kiosk runs fullscreen, and the v4 tablet screenshots show no header. Vertical budget: 12px padding + ~88px clock/weather + 10px gap + ~112px tile + 10px gap + two shutter rows (~122px each) + 12px padding ≈ 490px. Nothing was shrunk below the house readability floor (functional text ≥ 20px, labels 24px+) to force the fit.
Typography note — what the sizes are, and a discrepancy found Type sizes in the frame are the verified live values: clock 52px, weather 64° / 32px / 28px, shutter names 20px, shutter buttons 14px (sources: kiosk-clock.ts, kiosk-weather.ts, ha-shutter-card.ts). The review cited a “Casita Tablet theme at font scale 1.8, 28px minimum labels, 38px room names, 42px readouts, 104px clock” — those figures could not be verified: no font scale 1.8 and no such theme exist anywhere in the repo, no 38px room names exist, and the 104px clock is real but belongs to the Photos view (ha-immich-card.ts), not the Home view. One honest flag: the live shutter-button labels (14px) sit below the house readability floor — that is the live card’s property, shown faithfully here, not silently fixed in a mockup.
What is illustrative vs based on the live configuration Based on the live configuration: the Home view layout and card order (clock/weather horizontal stack, then a 2-column shutter grid), the four shutter names (Kid, Master, TV Area, Sofa), the card styling and button treatment, and the type sizes above. Illustrative: the clock time, the weather values (7°, Overcast, AQI 54), and the YouTube totals shown in the tile. Verified, not illustrative: the garbage dates (single-family Mokronos Górny, next Mon 9 Nov — Papier). Proposed, not decided: the 1-hour YouTube threshold, the 19:00 reminder time, both-adults / owner-only recipients. Open question: the current production tablets run the v4 rail UI (Album / Weather / Shutters / Sony / Watch), which has no single “Home” view — which v4 view the Alerts tile belongs in is still to be decided by the owner.

3 — Who gets what, and when

Anti-spam is part of the design: one message per event per day, no repeats, and an alert expires instead of lingering. If the schedule can’t be read, the tile says so out loud — it never just stays silent. The tile is the only monitoring signal for a stale schedule: there is no separate alert and no escalation in v1.
